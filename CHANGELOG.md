### Added

It reads one task on stdin, refuses a malformed or oversized task before launch, runs it on the stub VM host through the real vestibule (enforce mode), dropbox, inspector and decision chain, and prints one receipt bound to the gate's route ticket, tool call id and decision digest. Every receipt carries `real: false` and `mode: STUBBED`. The door holds its own guest deadline, since the vestibule listener has none. `demos/sandbox-demo/tests/route.rs` and `tests/route_mutation.rs` cover it.
- Step 12: `scripts/box_entry.py` `run` accepts `tool_call_id` and, when `BOX_LIVE_PROVE=1`, boots live `isolation-manager prove` under that id (no `skill:tool:path` invent). Unset env keeps the CI-shaped contract receipt. Fake, replay, and wrong-call-id denials still run through `accept_bound_receipt`. `tests/test_step12_box_entry_live.py` pins both paths. `always_invoked` stays false.
- `receipts/STEP-10b-2026-10-09.md`: re-prove of the Step 10 live harness on a clean isolation `main` tip (`9cdf7ee`) on the box after the scaffold checkout was moved aside (call id `step10b-20261010T025228Z`). Host HEAD and `git status` are named on the receipt. `always_invoked` stays false.
- `scripts/step10_live_harness.py` runs one write through real `Gate.evaluate` and `evaluate_tool_call`, seals gate and atoms digests through `box_entry`, and can feed those digests into live `isolation-manager prove` on the box. `tests/test_step10_live_e2e.py` fails first until those digests match recomputation. `receipts/STEP-10-2026-10-09.md` records the live call (`step10-20261010T010139Z`). `always_invoked` stays false.
- `receipts/INVENTORY-2026-10-09.md` records box and judge state (BUILT / TESTED / LIVE-PROVEN) before Step 10 wiring. `always_invoked` stays false.
- `receipts/STEP-9b-2026-10-09.md`: live jailer prove on the box against `main` tip `395319e` with call-bound digests.
- Demo job in the floor (`demo (make demo-all)`): it runs `make demo-all` on every push and pull request and fails on any FAIL row, then `scripts/readme_proof.py check` fails if a number in the README Proof section differs from the `out/summary.json` that run wrote. The README is rewritten from the code and carries a Proof section generated from `out/summary.json`.

### Fixed

- `isolation-manager prove` runs the vestibule listener as its own process (`vestibule-listen --enforce --harden`) instead of a thread. The listener's hardening writes the whole calling process into a 512 MiB, 64-pid cgroup leaf, so in-process it capped the rest of prove, and the inspector launch that copies the 1 GiB rootfs was OOM-killed inside that leaf (box kernel log, 2026-10-27: `oom_memcg=.../aegis-vestibule-66426-...scope`, `task=sudo`). A missing `vestibule-listen` binary is a refusal, not a fallback. `prove_never_runs_the_vestibule_in_process` fails if an in-process listener comes back. A live prove on the box after the fix passed every check with no OOM kill.
- License metadata: the Cargo workspace and `demos/sandbox-demo` now declare MIT, matching `LICENSE`. The license test and the README license paragraph say MIT.
- `isolation-manager prove` checks the jail id against the jail grammar (12 to 64 characters, letters, digits and dashes) before it prints the id or writes a chain row. A bad id, such as `../x`, an oversized id, or one with an escape or control character, is refused with a non-zero exit, is not echoed, and adds no chain row. Before this, such an id was printed raw and recorded in `launch` and `fail_closed` rows, since the check only ran inside the launch helper. `serve` goes through the same check. `crates/isolation-manager/tests/prove_jail_id_validate.rs` pins both paths, and the serve jail id tests now use ids that pass the grammar.
- The README keeps its Proof section as generated and adds why the box is a Firecracker microVM under the jailer and not a sandbox, the claim tense tags, and related work. The path figure sits under the microVM section.
- The path figure `docs/diagrams/isolation-layer-path.svg` starts at the jailer. The build spec dates the Ona bubblewrap write-up March 3, 2026, matching the byline on the linked page.
- `scripts/box_entry.py` spends each receipt id (the jail id when real prove prints none) and each box ticket digest once, in a locked `box-entry-spent.jsonl` beside the decision chain, so a live receipt or a box ticket replayed within 24 hours, sent by two calls at once, or sent again after a restart, is refused. A spent key expires 24 hours after it is spent, since the ticket carries no issue time, so a ticket kept longer than that is accepted again until atoms stamps an issue time. A call is refused when the store cannot be read or written, and a store with a bad row refuses every call until it is repaired. A prune writes the kept rows to a synced temp file and renames it over the store, so a failed or killed prune leaves the spent rows in place. The store defaults to /var/lib/isolation-manager beside the decision chain, so a host without that directory writable must set AEGIS_DECISION_CHAIN. `tests/test_box_entry_replay.py` pins the replay, restart, parallel, two process, failed prune and killed prune cases.
- The spent store and its `.lock` file are opened with O_NOFOLLOW, so a symlinked store or lock is refused and the call fails closed. The prune writes its temp file under a name from `mkstemp` beside the store, so a file planted there is not truncated, followed or waited on. `tests/test_box_entry_replay.py` pins the lock order against a concurrent prune, both symlink refusals and the planted temp cases.
- A prune that is killed after it makes its temp file leaves that file beside the spent store. The next prune, with the lock held, removes it when its name is the store name plus the exact `mkstemp` tail and `lstat` reads it as a regular file with one link owned by the running user. Symlinks, hard links, FIFOs, folders and look-alike names stay. A kill leaves the expired rows in the store, so the next call prunes and sweeps. `tests/test_box_entry_replay.py` pins the sweep, the cases it leaves alone, and that a prune that fails on a write error unlinks its own temp file.
- The vestibule listeners return a timed out error when a guest never connects, stalls mid frame, or drips a frame one byte at a time. One deadline covers accept and every read of the frame: the socket timeout is set to the time left before each read. That holds for the vsock timeout and for the unix socket serve, which has a 60 s deadline by default (`serve_one_with_deadline` takes a caller value). `crates/vestibule/tests/vsock_deadline.rs` and `uds_deadline.rs` pin both listeners.
- `vsock_roundtrip` in `aegis-common` bounds its accept and read by its timeout, so a guest that never connects, never closes, or drips bytes ends in a timed out error instead of holding `prove`. `crates/aegis-common/tests/vsock_roundtrip_deadline.rs` runs it against a socket stub, since Firecracker cannot boot on the dev host.
- `isolation-manager serve` names the jail id of the request in each reply. It used to read the jail id from the last chain row after prove, so under parallel calls, or after a refused call, a reply could name another caller's jail. `crates/isolation-manager/tests/serve_jail_id.rs` checks 960 parallel replies and a refused call. Each fresh jail id carries a per process counter, so two ids minted in the same nanosecond differ. The reply's jail id names the requested or assigned id, not a jail that ran.
- The changelog gate counts `crates/*/src/` and `scripts/` as user facing, so a change there needs a CHANGELOG line.
- `crates/inspector/src/verdict.rs` and `crates/isolation-manager/src/main.rs` are stored with LF line endings. Two comments in `verdict.rs` no longer use an em dash as a sentence break. The index bytes are LF.
- The voice, changelog and comment jobs source `resolve_base.sh` from the base the event names (the pull request base, the push's previous commit, else origin's default branch), copied into the runner's temp dir, and fail closed when that commit has none, so a change to the script cannot choose the range it is judged on. The changelog and comment gates themselves still run from the change's copy.
- The voice lint reads a relative clause after the noun in more places: "that" followed by a plain verb such as matter, count, exist or survive starts a relative clause after a count word, after a verb that takes the noun as an object, and after "the"; and a plural opening a sentence before "that" is the noun, since a plural cannot be an imperative. After a subject (it, this, results) the same "that" still marks the verb.
- Regex entries are keyed for the duplicate check by their parsed pattern, not their text: a group that only groups, a flag group that sets a flag already set, a repeat of exactly once and a one-letter class fold away, and letters compare without case except inside a group that turns case off. So redundant syntax cannot pad the exact count, and two case-guarded entries that differ only by case now count as two (the old text key folded them together).
- A regex entry skips the casefolded view when any group in the parsed pattern turns IGNORECASE off, however the flag group is spelled (`(?s-i:`, `(?-si:`, `(?x-i:`). The check used to look for the text `(?-i`, so other spellings matched a case they were written to skip, and the same characters inside a character class turned the casefolded view off for nothing.
- The public surface scan drops spacing combining marks (category Mc, such as U+0903) along with the other combining marks before matching, so one inside a name no longer hides it from a regex or short entry.
- The public surface scan and the voice lint fold look-alike letters with Unicode's confusables data (UTS #39, confusables.txt 18.0.0): every non-ASCII code point whose skeleton is one ASCII letter or digit (1,582 pairs), plus 30 small capitals, Cyrillic and Greek letters, and Latin letters with a tail, a bar or a turn that table leaves out (r with tail or fishhook, turned e, Ukrainian ie, l with bar, i with stroke, turned i). ASCII letters and digits are never folded. `scripts/gen_confusables.py` rebuilds the packed table; both files carry the same copy, and a test pins it and keeps the copies equal.
- The voice lint reads text after NFKC with format and invisible characters dropped, so a fullwidth or invisible-character spelling of a flagged word is caught. A "that" followed by its own subject (we, you, they, users, people and the like) starts a relative clause, so the noun before it names the character, while a "that" followed by a plain noun stays the object of a verb.
- With combining marks dropped, a combining-dot or dotted-capital-I spelling of a private entry is a duplicate of it and cannot pad the count, alongside the zero-width and case spellings already refused. Known gap: an entry that differs from another only by a separator (a spaced name and its one-word form) still counts as its own entry; keying duplicates on the separator-free form would refuse the live list, so that call is left to the maintainer.
- The look-alike fold also covers Armenian letters drawn like Latin ones (small o, u, h, n, g; capital O, U), fifteen Cherokee capitals drawn like Latin capitals, and the Latin small capitals NFKC leaves alone, so a name spelled with one of them is found. Lower-case Cherokee letters are not folded.
- Every capital-I look-alike folds to `I` in the public surface scan and the voice lint: Latin capital iota (U+0196), the dental click (U+01C0), Greek capital iota (U+0399), Cyrillic І (U+0406) and palochka (U+04C0), Runic isaz, Coptic iauda, Lisu I, Latin small capital I, epigraphic I longa, Old Italic I and Lydian I. Unicode's table folds each to lowercase `l`, its skeleton for ASCII `I`, so a name with an `i` written with one of them was not found. The override sits on top of the derived table in both files. Script and black-letter capital I, Roman numeral one and the mathematical capital iotas reach `I` through NFKC. ASCII `0`, `1` and `|` stay unfolded, since ASCII is never folded.
- Every private entry also reads the casefolded text, so a fold that case-insensitive matching alone misses (a sharp s for "ss") no longer hides a name from a regex or short entry. A regex that turns case sensitivity back on with `(?-i` skips that view and stays case-sensitive.
- The public surface scan drops combining marks (categories Mn and Me) after NFKC and the ignorable strip. NFKC composes a letter and a following mark into a different precomposed letter, so a name with a dot above, an accent, an overlay or an enclosing mark inside hid from regex and short entries (long plain entries already matched through the separator-free view). A dotted capital I matches the plain i entry in every form.
- The craft (voice) job runs the base branch's voice lint, loaded into the runner's temp dir, and fails closed when the base has none, so a change to `.floor/craft/voice_lint.py` no longer judges itself. `resolve_base.sh` is still sourced from the change under review.
- The public surface scan drops every Unicode default-ignorable code point (the combining grapheme joiner, Hangul fillers, variation selectors, tag characters, joiners, the soft hyphen, the byte-order mark and the rest of the set) and every format character after NFKC, so an invisible character inside a private name no longer hides it, in file text or in a tracked path, for plain and regex entries alike. The set is a table of ranges from Unicode's Default_Ignorable_Code_Point property.
- The public surface scan refuses repeats in the private list, so an entry already listed cannot be counted twice toward the exact entry count. A plain entry that repeats an earlier one after Unicode normalisation, case folding and whitespace folding (a case, spacing, zero-width or look-alike variant), a regex entry that is only a literal name and repeats a plain entry (it is keyed as that name), a regex entry that differs from an earlier one only by case, or another spelling of the canary, plain or regex, fails the load, naming entry indexes only. Entries that differ only by a separator, such as a spaced name and its one-word form, still load as two entries, and so does a real regex beside the plain name it widens. Known gap: distinct entries that name nothing private still count, so a list padded with junk can still meet the count.

A run outside the service now needs `AEGIS_DECISION_CHAIN` set, or write access to that directory.
- The voice lint flags every form of the word `underscore` (`underscores`, `underscored`, `underscoring`) as AI vocabulary in any use. Only the singular or plural noun that names the `_` character passes, and only in these shapes: right after a word that cannot start a subject (a determiner or possessive such as the, a or its, a position or count adjective such as leading or double, or a preposition other than before and after); right after the base, past or -ing form of a verb that takes it as an object, after first or last following a determiner, or after before or after, only when no determiner, possessive or object pronoun (it included) follows the word, and no that unless a verb or the that's own subject (we, you, they, users, people and the like) follows it, so a verb at the end of a clause, after a determiner and an ordinal, or after a clause-ending before or after is still caught; right after a word that can start a subject only when number agrees and no object follows (this, each or one with the singular; these, those, both, many, some, all or a number with the plural; a verb form that is also a plural noun, such as uses or matches, with the plural); right after that, or a bare first or last, only before the end of the sentence, is, are, was, were, the glyph in brackets or another character name in a list; joined to another word by a hyphen; at the start of a sentence before is, are, was, were, a preposition, the end of the sentence or the rest of a list of character names; in a list after another character name, when what follows ends the list, names another character, or is a subject verb such as splits or is; before the glyph in brackets or "as the character"; or quoted, when the closing quote is followed by punctuation, the end of the text, or a word such as is or wherever. A word on the left that can start a subject never exempts the word by itself. The commit sentence from eefcb9e and this branch's own commit messages pass.

### Changed

- Public files no longer carry a host home path, a host address, a personal email, the box host name, or the private name list in any recoverable form. `scripts/public_surface_scan.py` (standard library only) scans every tracked file and file name in every encoding (UTF-8, UTF-16 and UTF-32 at every alignment, binary with NUL bytes), after decoding (percent, escapes, HTML entities, base64, hex), normalising (NFKC, zero-width and look-alike letters), and rejoining split strings and continued lines. Built-in rules cover home paths, WSL network paths, private IPv4 and IPv6 ranges, emails, user@host names, and the box host name (by hash). The private list is never stored here: CI passes it as the `LEAK_DENYLIST` secret, which must hold the expected number of entries plus a canary that has to be found in all 24 planted forms. Hits print the rule and entry number, never the term, and a file name that carries a term prints as its index. The CI `public-surface` job loads the scanner from the base branch into a temp folder, installs nothing, is the only step that gets the secret, and fails closed when the base has no scanner or the secret is missing. The box host name and its trust domain left the tree: `BOX_LIVE_PROVE` and `BOX_SSH_TARGET` replace the old variable names, `scripts/sync-to-box.sh` replaces the old script, and the SPIRE issuer takes `BOX_HOSTNAME` (refuses when unset) and `BOX_TRUST_DOMAIN` (default `box.invalid`). The raw Step 12b receipt keeps its produced CRLF line endings, and its redacted digest is re-recorded. The guest home check uses the manager home resolved at runtime, and the manager unit runs as `isolation`.

- README drops identity-as-horizon. The four planes take identity as an argument. This roof stays the box.
